# OneLive Product Specification

## 1. 产品定义

OneLive 是一个面向跨境直播场景的演示型 MVP：

> 一名中国主播使用一部手机，以中文完成一次直播；系统同时生成面向北美、日本和西语市场的本地化数字分身直播体验。

正式副标题：

> 基于 5G 与边缘 AI 的多语言、多形象、跨平台实时数字分身直播

品牌表达：

> ONE SOURCE. MANY MARKETS. LIVE.

OneLive 不是普通翻译器、视频会议或真实直播平台。核心价值是把一次真人内容生产，转化为多个市场可同时观看的本地化数字分身体验，并清楚展示无线网络能力对实时体验的影响。

## 2. 产品目标

### P0：现场演示主链路

- 在没有手机、互联网或 API Key 时完整运行 Mock Demo。
- 同屏呈现一个主播源和三个差异化市场直播间。
- 让不同网络 Profile 在一秒内产生肉眼可见的画质、动作、字幕和频道状态变化。
- 让 Edge AI 与 QoD 的增益同时体现在视觉结果、指标和数据路径上。
- 使用 Demo Director 稳定完成 Connect → Congestion → Latency → Edge → QoD → Business 六步叙事。
- 1440 × 900 首屏无纵向滚动、无重叠，适合投屏。

### P1：真实采集与本地化链路

- 手机或桌面摄像头作为真实视频源。
- 手机与控制台通过 Socket.IO 配对并交换 WebRTC 信令。
- 在浏览器能力允许时获取实时媒体和连接状态。
- 使用字幕、浏览器 TTS 和程序化口型表现三种目标语言。
- 手机连接失败时可立即切换本机摄像头或 Mock Source。

### 非目标

- 真实直播平台推流与平台账号集成。
- 生产级运营商 QoD、MEC 或蜂窝定位。
- 电影级写实人脸替换、声音克隆或身份仿冒。
- 账号、支付、数据库、多租户和复杂权限系统。
- 对真实商业收益、转化率或带宽节省做未经验证的承诺。

## 3. 目标用户与场景

### 跨境品牌与中小商家

希望减少重复开播，以一次内容生产覆盖多个语言市场。

### 直播运营团队

需要统一观察主播源、三个市场频道、字幕、数字分身和网络状态。

### 运营商与边缘能力团队

需要直观看到高质量蜂窝上行、边缘推理和会话级网络保障对业务体验的影响。

### 比赛评委与现场观众

需要在 3–5 分钟内理解业务、体验差异和网络能力价值，不依赖阅读内部日志。

## 4. 核心用户故事

### 主播

- 作为主播，我可以扫描二维码进入专用采集页面，而不是操作复杂的桌面控制台。
- 我可以授权摄像头和麦克风、开始或结束直播、静音并切换前后摄像头。
- 网络中断后，我能看到明确的重连状态并返回原会话。
- 我能确认媒体不会被默认录制或持久化，并知道数字分身已获得授权。

### 演示者

- 作为演示者，我可以一键进入稳定初始状态，并用 Space 推进六步演示。
- 我可以在不依赖外部服务的情况下演示拥塞、高时延、Edge 和 QoD。
- 我能明确指出哪些数据是 LIVE、哪些是 EMULATED。
- 手机失败时，我可以在几十秒内切换本机摄像头或 Mock Source。

### 评委

- 作为评委，我能用肉眼区分带宽拥塞与高时延问题。
- 我能看到 Edge 缩短处理路径和响应时间，而不是只看到数字变绿。
- 我能看到 QoD 改变资源分配和频道状态，而不是无条件美化所有指标。
- 我能在收尾画面理解“一次直播，多市场同时开播”的商业价值。

## 5. 核心体验

### 5.1 全球直播控制台

控制台由四个强层级组成：

1. 顶部品牌和系统状态。
2. 左侧真人信号源。
3. 三个本地化数字分身直播间。
4. 底部端—网—边—云—直播间数据路径。

三市场采用配置驱动的 MarketProfile，默认包含：

| 市场 | 语言 | 视觉主题 | 优先级 |
| --- | --- | --- | --- |
| North America | English / en-US | Cobalt | 1 |
| Japan | 日本語 / ja-JP | Violet | 2 |
| LATAM + Spain | Español / es-ES | Amber | 3 |

市场模板由产品配置选择，不根据主播外貌推断国籍、种族或文化。

### 5.2 手机主播端

手机页面是专用采集端，核心顺序为：

1. 查看会话与连接状态。
2. 预览摄像头。
3. 开始或结束直播。
4. 静音、切换摄像头、选择演示台词。
5. 在断线时自动重连或返回会话。

主要控件触摸区域不少于 44 × 44 CSS px；页面尊重安全区，不把桌面控制台压缩到手机。

### 5.3 体验对比

对比模式使用同一输入并排展示：

- Cloud + Best Effort：更长路径、动作与字幕滞后、频道降级。
- Edge AI + QoD：更短路径、更低同步偏差、关键频道保持在线。

中央展示 E2E latency、Avatar FPS、A/V offset、Active channels 和 Experience score 的差值。模拟数据必须标记为 EMULATED。

### 5.4 商业收尾

核心文案：

> 一次直播，多市场同时开播。

收尾只陈述可解释价值：

- 减少重复开播。
- 降低多语主播组织难度。
- 加快跨境内容上线。
- 一次内容生产，多市场分发。
- 为直播会话引入 5G 上行、Edge AI 和 QoD 能力入口。

不展示未经验证的 ROI、收入或转化率。

## 6. 网络体验模型

### Premium 5G

- 三频道在线且画面清晰。
- 动作、字幕和语音接近同步。
- 数据脉冲稳定通过完整路径。

### Congested Network

- 可用带宽下降、RTT/抖动/丢包增加。
- 至少一个频道进入 LOW RES 或 BUFFERING。
- 画面出现像素化、冻结或帧率下降。
- 字幕和姿态队列延迟增加。

### Weak Coverage

- 主频道降为低清。
- 第二频道明显卡顿。
- 第三频道进入 AUDIO ONLY 或 PAUSED。
- 路径出现丢包、阻塞和信号衰减。

### High Latency

- 带宽仍可较高，但动作、字幕和口型出现明显时间错位。
- 画面可保持清晰，以此区别于弱覆盖。
- 显示 A/V SYNC WARNING。

### Edge AI

- 缩短应用模型中的处理路径。
- 降低姿态、翻译和语音返回时延。
- 不凭空增加无线带宽或修复所有画质问题。

### QoD

- 在拥塞条件下优先保证采集流和核心市场频道。
- 改变频道带宽分配与状态。
- 次要频道可以保持较低质量，不能把所有指标同时变为最佳值。

## 7. Demo Director

| 步骤 | 状态 | 评委应看到 |
| --- | --- | --- |
| 1 Connect | Premium 5G / Cloud / QoD Off | 一源驱动三市场，三频道在线 |
| 2 Congestion | Congested / Cloud / QoD Off | 像素化、卡顿、频道降级、指标转差 |
| 3 Latency | High Latency / Cloud / QoD Off | 清晰但滞后，字幕/口型错位，A/V warning |
| 4 Edge | High Latency / Edge / QoD Off | 路径缩短，动作和字幕响应改善 |
| 5 QoD | Congested / Edge / QoD On | 带宽重分配，核心频道恢复，三频道重新稳定 |
| 6 Business | 商业收尾 | 1 主播、3 语言、3 数字分身、3 市场、1 次生产 |

## 8. 数据来源与标记

每项指标必须能追溯来源：

- LIVE：真实媒体设备状态、会话存在状态，以及实际调用 getStats 后得到的 RTC 指标。
- EMULATED：Network Profile、处理延时、频道分配、体验评分、程序化姿态和预置翻译。

没有调用真实 API 时，不允许仅因为数值看起来合理就标记为 LIVE。

观众数和虚构平台标识只服务于演示构图，不代表真实平台数据。

## 9. 可靠性要求

- Mock Demo 不依赖外部服务。
- 手机断线可重连；同一角色的新连接可以替换旧连接。
- 无摄像头时可以切换本机摄像头或 Mock Source。
- 无语音识别时使用文字输入或预置台词。
- 无翻译 API 时使用预置翻译，并标记 EMULATED。
- 无目标语言 voice 时仍保留字幕与口型表现。
- WebGL 失败时应显示 2D Avatar 或明确的可恢复状态，不能留空。
- UI 不显示堆栈或内部错误。
- R 可以重置到稳定初始状态。

## 10. 可访问性与视觉质量

- 正常文本对比度至少 4.5:1，图形和大文本至少 3:1。
- 状态不能只依赖颜色，必须同时有文字、图标或线型变化。
- 键盘焦点清晰，图标按钮有可访问名称。
- 支持 prefers-reduced-motion；关闭持续扫描、呼吸和数据脉冲后，静态状态仍可读。
- 1440 × 900 控制台无纵向滚动。
- 390 × 844 手机端无横向溢出，固定控制条不遮挡内容。

## 11. 评分映射

### Demo 可演示性：30%

- Mock Safe Mode、Demo Director、快捷键、Presenter Mode。
- 手机失败的本机摄像头与 Mock 恢复路径。
- 端到端 3–5 分钟 runbook。

### 体验差异性：40%

- 四种网络 Profile 产生可视差异。
- 高时延与低带宽具有不同视觉语义。
- Edge 和 QoD 改善可通过画面、路径与指标共同验证。
- 专用对比模式直接展示体验差值。

### 商业价值：30%

- 一次内容生产覆盖三个市场。
- 市场化语言、数字形象、舞台和字幕。
- 清楚关联蜂窝上行、边缘推理和会话保障。
- 不以虚构财务数字替代真实价值叙事。

## 12. MVP 验收

完成状态以实际构建和测试结果为准。最低验收包括：

- npm run build、lint、test 和 test:e2e 在交付环境执行。
- demo:mock 可完成六步流程。
- 三市场卡和网络状态变化可见。
- Edge/QoD 改变体验模型，不只是修改文案。
- 手机路由能申请媒体权限，或明确回退到替代源。
- 1440 × 900、1920 × 1080、390 × 844 完成视觉检查。
- 文档与运行时 LIVE/EMULATED 标记一致。

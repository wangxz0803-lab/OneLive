# OneLive 演示台（预生成成片 + 可操作前端）

双击 `index.html` 即可打开，**不需要启动任何服务**，断网也能演示。页面先按四路视频的真实 `readyState` 显示本地预加载进度；素材就绪后自动进入控制台，异常或超时会提供降级进入路径，避免现场卡死。

---

## 现场怎么演（建议动线）

| # | 动作 | 评委看到什么 |
|---|------|--------------|
| 1 | 等加载页显示四路就绪，点 **「开始直播」** | PROGRAM 默认从原始中文信号开始；四窗同屏同时提供日语、拉美西语和印度英语版本，建立“中文输入 → 多市场内容”的起点 |
| 2 | 点 **日本频道** | PROGRAM 切日语版，右侧逐句显示中文原文 ↔ 日语译文。这不是加字幕，是整条内容重制 |
| 3 | 链路先切 **「高时延」**，再切 **「拥塞」** | 高时延保持 1080P / 30fps，但云端整路延时从 2.5 秒增加到约 4 秒；拥塞则触发降采样、丢帧和告警。完成后切回「优秀」 |
| 4 | 部署路径切 **「近端生成」** | 三路内容从云端返回的 +2500ms 追近到 +180ms；同时上行从单路 6.16 变为三路 18.48 Mbps，有限容量使三路公平降到**流畅 480P** |
| 5 | 开 **「QoD 业务保障」** | OneLive 业务从 Best Effort 的 8.25 Mbps 获得 **15 Mbps 保障预算**；两路 VIP 恢复 **1080P**，一路 Best Effort 保持 480P，服务差异肉眼可见 |
| 6 | 逐个开 **推流平台** | 出口 = 语言 × 平台 × 码率，平台流量表线性增长 |

完成六步主线后，可以点顶栏 **「未来体验」** 作为可选收尾：先展示由同一参考画面生成的正面主播、侧面互动和俯拍商品三个 AI 镜位关键帧，再切到空间直播概念。这个入口是独立概念层，不改变主 Demo 的网络、Edge 或 QoD 状态。

切换部署路径或会改变整路时延的网络档位时，PROGRAM 会短暂显示 **「正在同步媒体路径」**。页面会先冻结四路共同时间基准、提交最新目标，再同时恢复播放；这是为了避免四个本地视频在异步 seek 期间反复跳帧，通常在数百毫秒内完成。

> 第 4 步讲的是工程取舍，不是宣布某条路径绝对正确。云端以单路上行换取稍高的整体交付时延；近端可以落在设备、场馆边缘或运营商边缘，以更短路径换来多路并发上行压力。第 5 步再说明：QoD 像业务的 VIP 通道——运营商从小区调度资源中给 OneLive 更高、更稳定的可用预算；它不凭空增加物理频谱，而且预算不足时仍会按服务等级降级。切换前先按第 3 步回到「优秀」，避免把网络拥塞与部署位置混为一谈。

**键盘快捷键**（页脚也写着）：`空格` 开播 / 结束 · `1`–`4` 切链路档位（优秀 / 高时延 / 拥塞 / 弱覆盖）· `Q` `W` `E` 把日本 / 拉美 / 印度频道切到 PROGRAM（仅直播中生效）· `V` 打开 / 关闭未来体验，`Esc` 关闭。切回「原始中文」这一路只能点小窗，没有快捷键。

## 页面上有哪些控件（全部真实生效）

| 位置 | 控件 | 作用 |
|------|------|------|
| 左栏 | **部署路径**：云端生成 / 近端生成 | 云端上传一条原流后生成三路，近端在设备、场馆边缘或运营商边缘完成生成后多路上行；切换时同时改变相对原流时延与上行公式 |
| 左栏 | **语言频道**：日本 / 拉美 / 印度 | 真实影响分发路数、上行需求与出口带宽；关掉的频道无法切到 PROGRAM。状态灯和右侧文字会按实际链路显示“稳定 / 波动 / 受限”；QoD 下可直接看到两路 VIP 与一路 Best Effort 的差异 |
| 左栏 | **目标画质**：1080P / 720P / 480P | 码率 + 渲染缩放，实际作用于画面；实际画质由 ABR 决定，可能低于目标 |
| 左栏 | **字幕叠加** | PROGRAM 字幕条显隐 |
| 中栏 | **PROGRAM 主监看** + 三格指标（相对原流 / 路内音画 / 上行码率）+ 本地化文案对照 + **MULTIVIEW** 四窗 | 三路持续在播；点小窗只切主监看与监听总线；生成内容整体可晚于本地原流，但各路声音和画面保持同步 |
| 右栏 | **带宽账本** | 上行需求 / 实际上行 / 容量 / 缺口 / 链路余量 + ABR 降码告警 |
| 右栏 | **实时评论** | 跟随播出语言换语种，网络差时变慢 |
| 右栏 | **平台流量数据** | 每个平台一行，出口 = 语言 × 平台 × 码率 |
| 机架 | **音频总线** 三条推子 | 可拖动，真实驱动 VU 表与麦克风增益 |
| 机架 | **链路条件** 四档 + **QoD 业务保障** | 高时延只移动整路媒体时间轴；拥塞/弱覆盖再改变容量、丢包和抖动。QoD 只在近端 5G SA 多路上行时启用，把业务可用预算从 8.25M 提到 15M，并优先保障两路 VIP |
| 机架 | **分发平台** 五个 | 每关一个，出口带宽下降；顶栏图标同步 |
| 页脚 | **实测证据** 抽屉 | 列出本项目真实可运行部分的实测记录与来源文件 |
| 顶栏 | **未来体验** | 打开独立的多视图 / 空间直播概念层；加载四张本地 WebP 关键视觉，不新增视频解码器，不进入六步主状态机 |

### 未来体验如何讲

1. **多视图不是简单再加几个窗口。** 当前原型使用同一人物、服装、商品和时刻生成三个独立 AI 镜位关键帧，分别补充人物表达、横向空间关系和商品细节。它仍不是实时多机位采集，因此始终标记为 CONCEPT / EMULATED。
2. **内容维度会放大网络压力。** 按当前 6.16 Mbps/路模型，3 种语言 × 3 个视图会从 3 路、18.48 Mbps 扩展到 9 路、55.44 Mbps。这是基于当前演示码率的概念计算，不是实测蜂窝吞吐或商用 SLA。
3. **Edge 的价值是只做用户正在看的部分。** 切到“按需视口”后，演示账本回到 3 路、18.48 Mbps：Edge 根据用户视角生成或渲染当前视口，避免把全部视图长期全量上传和分发。
4. **空间直播先讲交互，再讲边界。** 拖动画面或角度滑杆展示自由观察设想；当前使用空间重建关键视觉和分层位移形成 2.5D 视差，没有实时三维重建。真实方案的负载取决于空间资产、编码方式和交互范围，因此界面不虚构固定 3D 码率。
5. **QoD 保障关键体验，不包办全部流量。** 在未来方案中优先保障当前视口、核心音频和交互控制；现有 15M 模型仍是两路 VIP 1080P、一路 Best Effort 480P，不会让九路内容全部变清晰。

## 换成你自己的素材

把文件丢进 `assets/` **覆盖同名文件**即可，无需改代码、无需运行脚本：

| 文件 | 用途 | 规格建议 |
|------|------|----------|
| `original-zh-demo.mp4` | 原始中文信号（CAM） | 竖屏 9:16，15 秒，H.264 + AAC，恒定 30fps |
| `japan-ja-demo.mp4` | 日本 · 日语频道（CH1） | 同上 |
| `latam-es-demo.mp4` | 拉美 · 西语频道（CH2） | 同上 |
| `india-en-demo.mp4` | 印度 · 英语频道（CH3） | 同上 |
| `original-zh.jpg` / `japan-ja.jpg` / `latam-es.jpg` / `india-en.jpg` | 各路封面（视频没加载时兜底） | 与对应视频同比例 |

四个 `*-demo.mp4` 都把本路 AAC 音频封装在视频内，并统一为 15 秒 / 30fps。浏览器直接维护每一路内部音画同步；页面只移动整路媒体时间轴来模拟 Cloud / Near-edge 的交付滞后。点击小窗以 90ms 淡入淡出切换监听，不换源、不 `load()`、不中断其他通道。未选中的视频继续静音运行，只有 PROGRAM 对应视频出声。

字幕/译文文案写死在 `index.html` 的 `SRC` 数组里（每路三句 + 中文原文），换素材时要一并改，否则文案对照与画面对不上。

尺寸不对也能用（`object-fit: cover` 会自动裁切），但比例接近效果最好。

> `assets/` 里还留着 `ch1.mp4` / `ch2.mp4` / `ch3.mp4` / `host.mp4` / `poster*.png` —— 那是旧占位素材，当前页面**一个都不引用**，可以直接删。

## 回归测试

从仓库根运行：

```bash
npm run test:demo          # 首次需先安装 Playwright Chromium
```

用 `demo/playwright.config.ts`（视口 1440×900，直接 `file://` 打开 `index.html`，不起任何服务，与现场"双击即开"同一条路径）。六个 spec：`smoke`（版面与结构）、`bandwidth`（带宽账本 / ABR / QoD）、`latency-audio`（相对原流时延与路内音画同步）、`decode-performance`（媒体帧持续更新）、`walkthrough`（六步动线，逐步截图到 `artifacts/demo-walkthrough/`）、`future-experience`（概念层、媒体不中断、网络账本、交互与响应式版面）。

> **截图与 CSS 过渡是隐性耦合。** `walkthrough.spec.ts` 里的 `shot()` 用 `waitForTimeout(400)` 等选中态的 `.24s` 过渡走完再截图。如果有人把过渡时间调长（`.net`、`.ctl`、`.tile` 上的 `transition`），截图会重新拍在动画中途、讲出与状态相反的故事，而**没有任何测试会失败**——回归网覆盖的是数字，不是像素。改过渡时长时请同步调 `shot()` 里的等待时间。

## 现场环境（投屏分辨率）

- **1440×900 / 1920×1080：已验收**，垂直与横向溢出均为 0，底部机架完整可见，右栏无内部滚动。投屏优先用这两档。
- **1366×768：可用，但右栏会内滚** ——页面不塌、底部机架完整，只是右栏（带宽账本 / 评论 / 平台流量）有约 83px 的内部滚动，看平台流量表要滚一下。
- **1280×800：可演**——左栏收窄但完整可见、拓扑开关可点（已修复曾经隐藏整个左栏的媒体查询，并有覆盖七档桌面宽度的回归测试）；右栏内滚约 51px。
- 浏览器用 Chrome，窗口最大化（不必按 F11 全屏）。演示前先在实际投屏设备上确认浏览器窗口宽度 > 1280px。

## 诚实边界（页脚已写明，评委问起来站得住）

- **预生成**：四段成片为提前生成并统一稳定帧率的干净母版，不是现场实时渲染
- **可控模拟**：云端/近端交付路径、网络参数、QoD、时延数值为模拟值，不代表生产部署或商用 SLA
- **真实计算**：交付帧率、网络劣化、带宽账本与 ABR 降级均在浏览器中实时计算
- **可追溯证据**：页脚「实测证据」抽屉列出本项目真实可运行部分的实测记录与来源文件
- **未来体验**：多视图使用 AI 生成镜位关键帧，空间模式使用空间重建关键视觉和 2.5D 视差；两者都属于 CONCEPT / EMULATED，不代表真实多机位、实时 3D 重建或生产 MEC

项目另有**真实可运行**的部分（引擎、真实 RTMP 推流、双端网络遥测、手机 App），见仓库根目录与 `engine/run-demo.ps1`，实测记录在 `docs/superpowers/`。

## 交付前人工验收

以下几条机器验不了，必须由人过一遍：

- [ ] **第 4 步观感与听感（最重要）**：Chrome 双击打开 `demo/index.html` → 开播并切日本频道 → 云端三路保持 1080P / 30fps 和路内音画同步，但整路相对本地原流晚约 2500ms；切「高时延」后增加到约 4 秒 → 切回「优秀」后点「近端生成」；三路追近到约 180ms，同时多路上行使三路降到 480P。再开 QoD，确认业务预算变为 15 Mbps，日本与拉美两路恢复 1080P，印度一路维持 480P。
- [ ] **断网可演**：拔网线 / 关 Wi-Fi 后双击 `demo/index.html`，确认四段视频都能播、PROGRAM 路有声音（页面无任何外链，字体已内联）。
- [ ] **用实际投屏设备走一遍完整六步动线**，确认分辨率、声音输出设备、以及浏览器是否拦了自动播放。
- [ ] **未来体验收尾**：直播中点「未来体验」，确认四路底层视频继续前进且没有重新加载；切三个视图、按需视口和空间模式，确认页面始终显示 CONCEPT / EMULATED 与能力边界。

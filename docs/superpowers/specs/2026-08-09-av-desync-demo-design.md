# OneLive 音画错位演示与本地化标签精简设计

## 目标

在不改动预录视频文件的前提下，让领导在导演流程中真实听见音画错位：第 3 步“高时延”明显不同步，第 4 步“Edge AI”明显收敛。同时移除本地化视频上可见的“AI 生成 · 已授权”标签，由演示者口头说明素材性质。

## 范围

- 仅影响右侧当前选中的本地化视频，以及使用同一视频播放器的对比视图标签。
- 第 3 步使用约 1000 ms 的音频延迟，人物口型先于声音；在保证演示现场肉眼可见的同时，避免呈现为过度夸张的严重故障。
- 第 4 步将音频延迟收敛到约 100 ms，表现体验改善。
- 其他网络场景保持 0 ms 播放偏移。
- 不修改原始 MP4，不生成新的音频文件，不接入真实网络整形或真实边缘节点。
- 不改动六步导演顺序、快捷键、WebRTC 输入、网络抽屉和安全演示回退。

## 播放架构

使用浏览器 Web Audio API 处理当前本地化 `<video>` 元素的音频：

1. 用户首次播放视频时，创建 `AudioContext`。
2. 通过 `MediaElementAudioSourceNode` 接管该视频的音频输出。
3. 音频经过 `DelayNode` 后连接到扬声器。
4. 导演状态变化时只更新 `DelayNode.delayTime`，视频播放、暂停、拖动、音量和原生控制条仍由同一个 `<video>` 元素负责。

这种方式不会产生两个独立播放器的漂移，也不会破坏原生播放控制。音频图只在用户播放后创建，避免浏览器自动播放限制和 React 开发模式重复挂载问题。

## 偏移规则

新增纯函数将演示状态映射为播放偏移：

| 场景 | 网络 Profile | 部署 | 播放偏移 |
| --- | --- | --- | --- |
| 正常、拥塞、弱网 | 非 `latency` | 任意 | 0 ms |
| 第 3 步高时延 | `latency` | `cloud` | 1000 ms |
| 第 4 步 Edge AI | `latency` | `edge` | 100 ms |

切换步骤时使用短时间参数过渡，避免声音瞬间爆音。切换市场或素材回退时销毁旧音频图，并在新视频首次播放时按当前步骤重新建立。

频道遥测中的 A/V SYNC 数值使用同一偏移规则：第 3 步显示 1000 ms 并出现同步警告，第 4 步显示 100 ms 并清除同步警告，避免实际听感和画面指标互相矛盾。

## 标签调整

- 从主市场视频和 Comparison 视频中删除“AI 生成 · 已授权”。
- 保留 `ja-JP`、`es-MX`、`en-IN` 等语言标识。
- 素材缺失时继续显示“原片回退”及恢复文件名，避免把回退素材当成本地化成片。
- 内部 `data-provenance="EMULATED"`、网络模拟标识和 LIVE / EMULATED 规则继续保留；本次只删除用户指定的可见素材标签。
- 同步移除配置类型中不再使用的本地化 `provenanceLabel`，并更新演示手册与决策记录。

## 失败处理

- 浏览器不支持 Web Audio、创建音频源失败或 `AudioContext.resume()` 被拒绝时，不中断视频播放；直接保留原生同步音频。
- 失败不影响导演推进、市场切换或 Mock Demo。
- 不向领导界面显示技术异常堆栈，浏览器控制台也不产生未捕获异常。

## 测试与验收

- 单元测试覆盖 0 / 1000 / 100 ms 的状态映射。
- 组件测试确认本地化视频不再渲染“AI 生成 · 已授权”，但仍显示语言标识和素材回退。
- Playwright 验证第 3 步视频暴露 1000 ms 偏移状态，第 4 步变为 100 ms，重置后恢复 0 ms。
- Playwright 验证主视图与 Comparison 均不存在该可见标签。
- 完整运行 build、lint、unit、E2E，并检查 1440 × 900 与 390 × 844 无布局回归。

## 真实性边界

这是浏览器端真实音频延迟，所以现场能听见音画不同步；但延迟值由导演状态驱动，仍属于 `EMULATED`，不能表述为真实运营商网络测量或真实 Edge 推理结果。

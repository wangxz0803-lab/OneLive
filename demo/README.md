# OneLive 演示台（预生成成片 + 可操作前端）

这是可直接发布的静态演示目录：公网部署将发布根目录指向 `demo/`、入口设为 `index.html` 即可，不需要构建命令、Node 服务、API Key 或外部 CDN。双击 `index.html` 也能离线打开。页面先按四路视频的真实 `readyState` 显示预加载进度；素材就绪后才允许开播，异常或超时会提供降级进入路径，避免现场卡死。

现场优先打开确认已更新的公网地址，并提前完整刷新一次让浏览器缓存素材。公网不可用时可双击 `start-demo.cmd`；它只使用本地文件，并自动避开已占用端口。启动器只复用同一目录的演示进程；其他目录或旧包占用端口时自动另选端口，避免打开错版本。

## 现场怎么演（建议动线）

| # | 动作 | 评委看到什么 |
|---|------|--------------|
| 1 | 等加载页显示四路就绪，点 **「开始直播」** | PROGRAM 默认从原始中文信号开始；四窗同屏展示日本日语、海湾阿语和拉美西语版本，建立“一个果园现场 → 三个海外市场”的起点 |
| 2 | 点 **海湾频道** | PROGRAM 切阿拉伯语版本，右侧逐句显示中文原文 ↔ 阿语译文。这不是加字幕，是整条内容重制 |
| 3 | 链路切 **「高时延」**，观察时延瀑布，再开一次 **「业务保障服务」** | 云端总时延显示为“上行 720ms + 云端处理 1250ms + 下行 1995ms = 3.97s”；保障后上行降至 260ms、下行降至 940ms，总时延降至 2.45s，云端处理仍为 1250ms。看完关闭保障，再切「拥塞」观察降采样、丢帧和告警，最后回到「优秀」 |
| 4 | 部署路径切 **「端侧生成」** | 三路内容从云端返回的 +2500ms 追近到 +180ms；同时上行从单路 5.16 变为三路 15.48 Mbps。8 Mbps 业务预算预留 20% 后编码可用 6.4 Mbps，使三路公平降到**流畅 480P** |
| 5 | 开 **「业务保障服务」** | OneLive 获得 **15 Mbps 业务保障预算**，预留余量后编码可用 12 Mbps；当前节目与一个核心市场恢复 **1080P**，另一路保持 480P，服务差异肉眼可见 |
| 6 | 逐个开 **推流平台** | 出口 = 语言 × 平台 × 码率，平台流量表线性增长 |

完成六步主线后，可以点顶栏 **「未来体验」** 作为可选收尾：入口先播放 1 分 46 秒的 OneLive 愿景影片，完整说明真实现场空间化、全球访问、个性化体验与 Agent 运营闭环；右上角或片尾再点 **「进入空间交互」**，进入上海外滩三机位、连续环绕视口和预生成 3D 人物原型。这个入口是独立概念层，不改变主演示的网络、部署路径或保障服务状态。

切换部署路径或会改变整路时延的网络档位时，PROGRAM 会短暂显示 **「正在同步媒体路径」**。页面会先冻结四路共同时间基准、提交最新目标，再同时恢复播放；这是为了避免四个本地视频在异步 seek 期间反复跳帧，通常在数百毫秒内完成。

> 第 3 步讲清保障服务的边界：它稳定终端与应用服务器之间的指定数据流，能减少网络排队、抖动余量和由此产生的缓冲，但不会加速云端 AI。第 4 步讲部署取舍：云端以单路上行换取更长处理与回传链路；端侧以更短路径换来多路并发上行压力。第 5 步再展示同一保障服务在端侧场景下的容量和优先级收益。切换前先回到「优秀」并关闭保障，避免状态叠加。

**键盘快捷键**（页脚也写着）：`空格` 开播 / 结束 · `1`–`4` 切链路档位（优秀 / 高时延 / 拥塞 / 弱覆盖）· `Q` `W` `E` 把日本 / 海湾 / 拉美频道切到 PROGRAM（仅直播中生效）· `V` 打开 / 关闭未来体验，`Esc` 关闭。切回「原始中文」这一路只能点小窗，没有快捷键。

## 页面上有哪些控件（全部真实生效）

| 位置 | 控件 | 作用 |
|------|------|------|

| 左栏 | **语言频道**：日本 / 海湾 / 拉美 | 真实影响分发路数、上行需求与出口带宽；关掉的频道无法切到 PROGRAM。状态灯和右侧文字会按实际链路显示“稳定 / 波动 / 受限”；保障开启后可直接看到两路优先频道与一路普通频道的差异 |
| 左栏 | **目标画质**：1080P / 720P / 480P | 码率 + 渲染缩放，实际作用于画面；实际画质由 ABR 决定，可能低于目标 |

| 右栏 | **带宽账本** | 上行需求 / 实际上行 / 容量 / 缺口 / 链路余量 + ABR 降码告警 |
| 右栏 | **实时评论** | 跟随播出语言换语种，网络差时变慢 |
| 右栏 | **平台流量数据** | 每个平台一行，出口 = 语言 × 平台 × 码率 |
| 机架 | **音频总线** 三条推子 | 可拖动，真实驱动 VU 表与麦克风增益 |

| 机架 | **分发平台** 五个 | 每关一个，出口带宽下降；顶栏图标同步 |

| 顶栏 | **未来体验** | 先打开本地愿景影片；可从影片右上角或片尾进入空间直播制作台与观众自由视角，不进入六步主状态机 |

## 演示参数依据

- **编码档位**：1080P 5.0M、720P 2.5M、480P 1.2M、360P 0.63M、240P 0.5M 是跨平台演示预设，不是统一行业标准。数量级参考 [Vimeo OTT Live](https://help.vimeo.com/hc/en-us/articles/12427305044497-Get-started-with-Vimeo-OTT-Live) 的 1080P 5256kbps、720P 2756kbps、360P 628kbps，以及 [YouTube Live](https://support.google.com/youtube/answer/2853702) 按编码格式给出的直播码率区间。
- **链路余量**：编码预算按业务预算的 80% 计算，即固定预留 20%；依据是 [YouTube Streaming Tips](https://support.google.com/youtube/answer/2853856) 对直播上传带宽的余量建议。
- **网络档位**：8M / 2.5M / 1M 是用于触发确定性体验差异的 EMULATED 场景预算，不代表 5G、4G 的固定能力。其数量级只参考真实移动网络存在从低于 2M 到 20M 以上的宽分布，例如 [Ofcom Mobile Matters 2025](https://www.ofcom.org.uk/siteassets/resources/documents/research-and-data/telecoms-research/mobile-matters/2025/mobile-matters-2025.pdf)。
- **时延语义**：总量由上行、处理、下行含缓冲三段相加；网络档的“基线 RTT”是另一参考量，不可重复加到三段之上。下行分发和播放缓冲在卡片下方展开。3GPP Packet Delay Budget 也不是跨境端到端总时延或 RTT；参见 [3GPP TS 23.501](https://www.etsi.org/deliver/etsi_TS/123500_123599/123501/18.05.00_60/ts_123501v180500p.pdf)。
- **波动预算**：云端高时延预设的上行 ±180ms、下行 ±300ms，在双流保障后展示为 ±25ms 和 ±50ms。数字仅为确定性模拟预算，静态条表示前后差异，不是实测抖动或统计置信区间；不让视频反复 seek 来制造波动。
- **终端与会话**：云端路径的一个按钮编排两个示例终端的独立保障会话，实际产品需要分别具备网络覆盖、设备授权和可用 profile；不能据此宣称全球观众都被保障。端侧只展示主播侧上行优先级/吞吐服务。4G 预设不可用是本演示配置，不是协议限制。
- **处理预算**：云端 1250ms、端侧 100ms 以及分发路径的差异是场景假设。没有在相同硬件、模型、语言和远端观看条件下实测，不能把 180ms 当作端侧跨境直播的性能承诺。
- **保障服务**：页面名称是对 QoD 类网络能力的业务化表达。GSMA Open Gateway QoD 支持为终端与应用服务器之间的指定数据流请求稳定时延或优先吞吐；端到端时延仍包含运营商控制范围之外的部分。演示中的分段数值和 15M 业务预算是确定性模拟，不是标准固定档位；参见 [GSMA Open Gateway Quality on Demand](https://open-gateway.gsma.com/docs/quality-on-demand/api-reference)。

### 未来体验如何讲

1. **先播放愿景影片。** 它负责讲完整产品故事，不要在播放中频繁操作页面；影片结束后用一句话收束：“同一个真实现场，面向不同用户生成不同的空间体验，并把兴趣反馈给直播团队。”
2. **再讲制作链路。** 点击“进入空间交互”。三个相机示意不是当前真实设备，而是未来左前、正面、右前多机位输入；数据经5G并发上行，在云端完成时空对齐、空间重建和当前视口渲染。
3. **最后切到观众端。** 点击“进入3D空间”，上下左右拖动可围绕三维人物观察，双击复位。人物是预生成 GLB 的本地实时渲染；制作台视频和观众端三维人物是两个顺序展示层，因此不是实时多机位三维重建。
4. **网络对比留在主演示。** 当前空间原型不展示独立的网络档位或保障开关，避免重复操作。未来的多机位上行和视口下行是产品设想，不是当前实测能力。
5. **声音与视角分离。** 环绕视频保持静音，按钮播放预录素材原声的独立音频通道，避免拖动视角时倒放声音。该音频不是空间音频或实时直播音轨。

## 换成你自己的素材

把文件丢进 `assets/` **覆盖同名文件**即可，无需改代码、无需运行脚本：

| 文件 | 用途 | 规格建议 |
|------|------|----------|
| `original-zh-demo.mp4` | 原始中文信号（CAM） | 360×640 竖屏，14 秒，H.264 + AAC，恒定 30fps，Fast Start |
| `japan-ja-demo.mp4` | 日本 · 日语频道（CH1） | 同上 |
| `gulf-ar-demo.mp4` | 海湾 · 阿拉伯语频道（CH2） | 同上 |
| `latam-es-demo.mp4` | 拉美 · 西语频道（CH3） | 同上 |
| `original-zh.jpg` / `japan-ja.jpg` / `gulf-ar.jpg` / `latam-es.jpg` | 各路封面（视频没加载时兜底） | 与对应视频同比例 |

四个素材文件都把本路 AAC 音频封装在视频内，并统一为 14 秒 / 30fps。阿拉伯版本已移除原混杂音轨，将独立配音加速约 1.21% 并延后 104ms 后重新封装，使语音首尾与人物开口区间对齐。浏览器直接维护每一路内部音画同步；页面只移动整路媒体时间轴来模拟 Cloud / On-device 的交付滞后。点击小窗以 90ms 淡入淡出切换监听，不换源、不 `load()`、不中断其他通道。未选中的视频继续静音运行，只有 PROGRAM 对应视频出声。

字幕/译文文案写死在 `index.html` 的 `SRC` 数组里（每路三句 + 中文原文），换素材时要一并改，否则文案对照与画面对不上。

尺寸不对也能用（`object-fit: cover` 会自动裁切），但比例接近效果最好。

> `assets/` 里仍保留此前的卖锅素材作为回退文件，但当前页面**一个都不引用**；现场加载的只有上表四份果园素材。

## 回归测试

从仓库根运行：

```bash
npm run test:demo          # 首次需先安装 Playwright Chromium
```

用 `demo/playwright.config.ts`（视口 1440×900，通过本地静态服务打开，与公网发布同一路径）。六个 spec：`smoke`（版面与结构）、`bandwidth`（带宽账本 / ABR / QoD）、`latency-audio`（相对原流时延与路内音画同步）、`decode-performance`（媒体帧持续更新）、`walkthrough`（六步动线，逐步截图到 `artifacts/demo-walkthrough/`）、`future-experience`（3D 概念层、后台解码隔离、无重载恢复、交互与响应式版面）。

> **截图与 CSS 过渡是隐性耦合。** `walkthrough.spec.ts` 里的 `shot()` 用 `waitForTimeout(400)` 等选中态的 `.24s` 过渡走完再截图。如果有人把过渡时间调长（`.net`、`.ctl`、`.tile` 上的 `transition`），截图会重新拍在动画中途、讲出与状态相反的故事，而**没有任何测试会失败**——回归网覆盖的是数字，不是像素。改过渡时长时请同步调 `shot()` 里的等待时间。

## 现场环境（投屏分辨率）

- **1440×900 / 1920×1080：已验收**，垂直与横向溢出均为 0，底部机架完整可见，右栏无内部滚动。投屏优先用这两档。
- **1366×768：可用，但右栏会内滚** ——页面不塌、底部机架完整，只是右栏（带宽账本 / 评论 / 平台流量）有约 83px 的内部滚动，看平台流量表要滚一下。
- **1280×800：可演**——左栏收窄但完整可见、拓扑开关可点（已修复曾经隐藏整个左栏的媒体查询，并有覆盖七档桌面宽度的回归测试）；右栏内滚约 51px。
- 浏览器用 Chrome，窗口最大化（不必按 F11 全屏）。演示前先在实际投屏设备上确认浏览器窗口宽度 > 1280px。

### 公网发布与性能约束

- GitHub 提交完整源码，但公网发布根目录只指向 `demo/`；入口为 `index.html`，无需构建命令。
- `demo/` 中所有运行依赖均为本地相对路径。Three.js 已打进 `future-3d.bundle.js`，现场不访问第三方脚本、字体或模型服务。
- 六段 MP4 均为 H.264 / 30fps / Fast Start。四路主视频总计约 4.1MB；21.2MB 愿景影片只预读元数据，点击“未来体验”后才播放；空间交互首次进入后才加载约 8.3MB 的 GLB 与全景资源。
- 四格小窗由浏览器直接合成，不再逐帧复制四张 Canvas；只有 PROGRAM 主监看保留 Canvas，用于真实表现降采样、丢帧和抖动。
- 打开愿景影片或空间交互时，后台四路主视频暂停解码；关闭后从原时间点恢复且不会重新下载。3D 渲染限制为 30fps、最高 1.25 倍像素密度，页面不可见时停止渲染。
- `demo/_headers` 为支持该文件的静态托管平台设置入口不缓存、资源短期缓存。其他 Nginx / 对象存储部署至少应支持 MP4 `Range` 请求。

## 诚实边界（页脚已写明，评委问起来站得住）

- **预生成**：四段成片为提前生成并统一稳定帧率的干净母版，不是现场实时渲染
- **可控模拟**：云端/端侧交付路径、网络参数、保障服务及分段时延数值为模拟值，不代表生产部署或商用 SLA；网络档位是场景预设，不代表 4G/5G 的固定能力
- **真实计算**：交付帧率、网络劣化、带宽账本与 ABR 降级均在浏览器中实时计算
- **可追溯证据**：页脚「实测证据」抽屉列出本项目真实可运行部分的实测记录与来源文件
- **未来体验**：多视图使用 AI 生成镜位关键帧，空间模式使用空间重建关键视觉和 2.5D 视差；两者都属于 CONCEPT / EMULATED，不代表真实多机位、实时 3D 重建或生产 MEC

项目另有**真实可运行**的部分（引擎、真实 RTMP 推流、双端网络遥测、手机 App），见仓库根目录与 `engine/run-demo.ps1`，实测记录在 `docs/superpowers/`。

## 交付前人工验收

以下几条机器验不了，必须由人过一遍：

- [ ] **主链路观感与听感（最重要）**：开播并切本地化频道 → 云端优秀档确认 250 + 1250 + 1000 = 2500ms；高时延档确认 720 + 1250 + 1995 = 3965ms → 开启保障，确认上行降 460ms、下行降 1055ms、处理不变，总时延 2450ms → 关闭保障并切回优秀 → 切「端侧生成」，确认总时延约 180ms，同时三路 15.48 Mbps 需求超过 6.4 Mbps 编码预算并降至 480P → 再开保障，确认业务预算 15 Mbps、编码预算 12 Mbps，两路恢复 1080P、一路维持 480P。
- [ ] **断网可演**：拔网线 / 关 Wi-Fi 后双击 `demo/index.html`，确认四段视频都能播、PROGRAM 路有声音（页面无任何外链，字体已内联）。
- [ ] **用实际投屏设备走一遍完整六步动线**，确认分辨率、声音输出设备、以及浏览器是否拦了自动播放。
- [ ] **未来体验收尾**：直播中点「未来体验」，确认影片有声流畅播放、四路底层视频暂停以释放解码资源；用右上角进入空间交互，切三个视图并进入3D空间，确认上下左右拖动流畅；关闭后四路从原位置恢复且没有重新加载。

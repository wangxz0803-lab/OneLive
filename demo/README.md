# OneLive 演示台（预生成成片 + 可操作前端）

双击 `index.html` 即可打开，**不需要启动任何服务**，断网也能演示。

---

## 现场怎么演（建议动线）

| # | 动作 | 评委看到什么 |
|---|------|--------------|
| 1 | 点 **「开始直播」** | 四窗同屏：一位中国主播说中文，同时播出日语和服版、拉美西语版、印度英语版——场景与服装整体本地化 |
| 2 | 点 **日本频道** | PROGRAM 切日语版，右侧逐句显示中文原文 ↔ 日语译文。这不是加字幕，是整条内容重制 |
| 3 | 链路切 **「拥塞」** | 画面按丢包真丢帧、按带宽真降采样、按抖动真延迟绘制，画质自动降级并告警。切回「优秀」 |
| 4 | 生成位置切 **「端侧生成」** | 上行需求 6.16 → 18.48 Mbps，缺口转负 −10.23，ABR 强制降到 480P；**同时** E2E 860 → 215ms，音画错位 440 → 40ms，**声音当场追上口型** |
| 5 | 开 **「QoD 保障」** | 保障容量抬到 22 Mbps，三路并发装得下，画质弹回 1080P 且保持同步 |
| 6 | 逐个开 **推流平台** | 出口 = 语言 × 平台 × 码率，平台流量表线性增长 |

> 第 4 步是全场转折点：评委自己会得出结论——云端省上行但跨洲回传让音画错位到无法互动；端侧能实时同步，代价是上行翻三倍而链路吃不下。第 5 步给出唯一的解。

**键盘快捷键**（页脚也写着）：`空格` 开播 / 结束 · `1`–`4` 切链路档位（优秀 / 良好 / 拥塞 / 弱覆盖）· `Q` `W` `E` 把日本 / 拉美 / 印度频道切到 PROGRAM（仅直播中生效）。切回「原始中文」这一路只能点小窗，没有快捷键。

## 页面上有哪些控件（全部真实生效）

| 位置 | 控件 | 作用 |
|------|------|------|
| 左栏 | **生成位置**：云端生成 / 端侧生成 | 只改上行侧公式：云端 1 路上行，端侧 = 在播语言路数；同时切换时延与音画错位模型 |
| 左栏 | **语言频道**：日本 / 拉美 / 印度 | 真实影响分发路数、上行需求与出口带宽；关掉的频道无法切到 PROGRAM |
| 左栏 | **目标画质**：1080P / 720P / 480P | 码率 + 渲染缩放，实际作用于画面；实际画质由 ABR 决定，可能低于目标 |
| 左栏 | **字幕叠加** | PROGRAM 字幕条显隐 |
| 中栏 | **PROGRAM** + 三格指标（E2E 时延 / A-V SYNC / 上行码率）+ 本地化文案对照 + **MULTIVIEW** 四窗 | 点小窗切播出路 |
| 右栏 | **带宽账本** | 上行需求 / 实际上行 / 容量 / 缺口 / 链路余量 + ABR 降码告警 |
| 右栏 | **实时评论** | 跟随播出语言换语种，网络差时变慢 |
| 右栏 | **平台流量数据** | 每个平台一行，出口 = 语言 × 平台 × 码率 |
| 机架 | **音频总线** 三条推子 | 可拖动，真实驱动 VU 表与麦克风增益 |
| 机架 | **链路条件** 四档 + **QoD 保障** | 容量 / RTT / 丢包 / 抖动；QoD 受接入制式约束（5G SA 22 Mbps、5G NSA 12 Mbps，4G 灰置不可用） |
| 机架 | **分发平台** 五个 | 每关一个，出口带宽下降；顶栏图标同步 |
| 页脚 | **实测证据** 抽屉 | 列出本项目真实可运行部分的实测记录与来源文件 |

## 换成你自己的素材

把文件丢进 `assets/` **覆盖同名文件**即可，无需改代码、无需运行脚本：

| 文件 | 用途 | 规格建议 |
|------|------|----------|
| `original-zh.mp4` | 原始中文信号（CAM） | 竖屏 9:16，12–20 秒，可循环，**需带音轨** |
| `japan-ja.mp4` | 日本 · 日语频道（CH1） | 同上 |
| `latam-es.mp4` | 拉美 · 西语频道（CH2） | 同上 |
| `india-en.mp4` | 印度 · 英语频道（CH3） | 同上 |
| `original-zh.jpg` / `japan-ja.jpg` / `latam-es.jpg` / `india-en.jpg` | 各路封面（视频没加载时兜底） | 与对应视频同比例 |

编码用 **H.264 / MP4**。**音轨是必需的**：PROGRAM 那一路的声音直接取自同名 mp4（`<audio>` 单独播放同一文件），音画错位演示全靠它。四个监看小窗的 `<video>` 恒为静音，只有 PROGRAM 路出声。

字幕/译文文案写死在 `index.html` 的 `SRC` 数组里（每路三句 + 中文原文），换素材时要一并改，否则文案对照与画面对不上。

尺寸不对也能用（`object-fit: cover` 会自动裁切），但比例接近效果最好。

> `assets/` 里还留着 `ch1.mp4` / `ch2.mp4` / `ch3.mp4` / `host.mp4` / `poster*.png` —— 那是旧占位素材，当前页面**一个都不引用**，可以直接删。

## 回归测试

从仓库根运行：

```bash
npm run test:demo          # 23 passed
```

用 `demo/playwright.config.ts`（视口 1440×900，直接 `file://` 打开 `index.html`，不起任何服务，与现场"双击即开"同一条路径）。四个 spec：`smoke`（版面与结构）、`bandwidth`（带宽账本 / ABR / QoD）、`latency-audio`（时延、音画错位、音频对齐）、`walkthrough`（六步动线，逐步截图到 `artifacts/demo-walkthrough/`，该目录已在 `.gitignore` 里）。

> **截图与 CSS 过渡是隐性耦合。** `walkthrough.spec.ts` 里的 `shot()` 用 `waitForTimeout(400)` 等选中态的 `.24s` 过渡走完再截图。如果有人把过渡时间调长（`.net`、`.ctl`、`.tile` 上的 `transition`），截图会重新拍在动画中途、讲出与状态相反的故事，而**没有任何测试会失败**——回归网覆盖的是数字，不是像素。改过渡时长时请同步调 `shot()` 里的等待时间。

## 现场环境（投屏分辨率）

- **1440×900 / 1920×1080：已验收**，垂直与横向溢出均为 0，底部机架完整可见，右栏无内部滚动。投屏优先用这两档。
- **1366×768：可用，但右栏会内滚** ——页面不塌、底部机架完整，只是右栏（带宽账本 / 评论 / 平台流量）有约 83px 的内部滚动，看平台流量表要滚一下。
- **1280×800：可演**——左栏收窄但完整可见、拓扑开关可点（已修复曾经隐藏整个左栏的媒体查询，并有覆盖七档桌面宽度的回归测试）；右栏内滚约 51px。
- 浏览器用 Chrome，窗口最大化（不必按 F11 全屏）。演示前先在实际投屏设备上确认浏览器窗口宽度 > 1280px。

## 诚实边界（页脚已写明，评委问起来站得住）

- **预生成**：四段成片为提前生成的素材，不是现场实时渲染
- **可控模拟**：网络参数、Edge、QoD、时延数值为模拟值，不代表生产部署或商用 SLA
- **真实计算**：网络劣化对画面的影响、带宽账本与 ABR 降级均为实时计算
- **可追溯证据**：页脚「实测证据」抽屉列出本项目真实可运行部分的实测记录与来源文件

项目另有**真实可运行**的部分（引擎、真实 RTMP 推流、双端网络遥测、手机 App），见仓库根目录与 `engine/run-demo.ps1`，实测记录在 `docs/superpowers/`。

## 交付前人工验收

以下几条机器验不了，必须由人过一遍：

- [ ] **音画错位听感（最重要）**：Chrome 双击打开 `demo/index.html` → 点「开始直播」→ 切日本频道 → 在**云端**拓扑下听到日语配音明显晚于口型 → 点「端侧生成」，会有一次短暂的静默重建，随即声音与口型立即对齐（这是"交付路径重建"的声音，不是变速追赶）。另外可切到 CAM 原始信号验证：本地监看应始终满帧、零错位，指标条显示「本地」。这条是第 4 步的全部说服力所在，自动化测的是数值不是听感。
- [ ] **断网可演**：拔网线 / 关 Wi-Fi 后双击 `demo/index.html`，确认四段视频都能播、PROGRAM 路有声音（页面无任何外链，字体已内联）。
- [ ] **用实际投屏设备走一遍完整六步动线**，确认分辨率、声音输出设备、以及浏览器是否拦了自动播放。
